# Bot creation, conversations and performance

The [Grok bot reference](https://flaviocopes.com/grok-bot/) informs the presentation, not a claim of feature parity.

- Add new bot offers six suggestions and cloud/available managed-host deployment. Managed execution requires independent acknowledgement; provider and transcript-sharing grants are not implied. Uncertain creation retries retain their request ID while the unchanged form stays mounted. This is not browser-reload recovery.
- AI keys lists saved credentials only in the shared TanStack table (search, sorting, pagination and filter popovers). Add new bot uses the same searchable provider/model selectors. AI keys uses a responsive provider table and shared UI controls in an Add/Replace modal. Four API-key providers expose their pinned model catalog; the managed catalog also includes native Codex OAuth models. Model search bounds rendered options, not the searchable catalog. Saving a model preference does not change existing bots, grant access, validate billing or restrict a provider credential to that model.
- Per-bot **Settings** slides into the chat container, shifting chat at container widths of at least 860px and overlaying it otherwise. The narrow layout makes covered chat inert and traps panel focus; Escape restores focus and reduced-motion preferences disable animation. The options menu contains Settings, a shared separator, Clear history and Delete bot. Account settings and device linking remain in general settings (device linking is under Server). Routine prompt/time/timezone values are **drafts only**, saved with `enabled:false`. There is no scheduler, event-trigger service or automatic prompt execution.
- Below preferences, a shared separator precedes outlined right-chevron links to Routines, Connection and AI settings. Managed bots also have **Agent actions**. Pages animate forward/back with reduced-motion support; drafts and navigation focus survive page changes. Connection shows owner-scoped, freshness-aware metadata without reconnecting automatically. AI settings distinguishes requested managed revisions, shared cloud defaults and agent-specific key grants; it links to existing account controls rather than inventing per-bot overrides. Codex OAuth has a separate Add new key sign-in flow and is never pasted into the API-key field; OAuth-capable managed runtimes receive access tokens only after separate agent consent.
- **Agent actions** sends revision-checked stop/resume, reload and runtime-removal requests to the existing manager protocol, not model prompts. Operations distinguish acceptance from runtime acknowledgement. An uncertain request retains its ID for explicit retry; there is no automatic retry. Runtime removal preserves chat history and workspace volumes, with permanent purge still separate. **Compact agent** now uses the authenticated manager/runtime protocol and is enabled only for an updated, capable host. It changes the Pi context, not Rue chat. Provider/model changes stop the agent with explicit consent; AI-key selection lists saved API keys and OAuth connections; compatible keys require explicit terminal-scoped exposure consent. OAuth selection requires a Codex-configured agent, a ready connection and an OAuth-capable host. Account-wide key replacement is a separate action with shared-scope confirmation. Detailed explanations live in settings docs rather than the action panel.
- **Agent status**, also in the three-dot menu, shows observed Pi directory/branch, provider/model, thinking level, context and usage with freshness labels. Managed runners report to the manager as well; linked Pi requires independent `/rue share-status` consent. See [status details](./agent-status.md) and [compaction rollout](./managed-compaction.md).
- Conversations group visible messages by local calendar day. Transport chunks and superseded placeholders are resolved before grouping. The working avatar respects reduced-motion preferences.
- Every bubble has a one-line ellipsized title beside its status when present. Received means a finalized mirror arrived, not that its task succeeded; explicit failed/interrupted outcomes show Error. Existing runtimes need a bridge update before emitting the new outcome metadata.
- Clear history is a confirmed, owner-scoped cloud operation, guarded against stale message tails and any active run for that owner. It removes messages and cascading parts/attachments but retains bot settings and unsent drafts. Remote history clearing is disabled: removing a Rue mirror would not reset Pi memory. Managed deletion still requires the existing destroy/purge controls.
- Completion pills describe a **message**, not the entire bot task. PR/code actions canonicalize reported GitHub links; they do not verify PR existence, approve changes or merge code.
- General settings now labels the connections page **Agents**, with shared Managed agents and Linked agents tables; row actions retain lifecycle and connection controls. Tenancy API keys also uses the shared table and owner-scoped creation modal. Live list/owner endpoints still returned HTTP 503 during the latest development check; no local fallback or unreviewed Tenancy rollout was performed.
- Skills, integration authorization, event routines and bot collaboration from the reference remain separate backend work.

The latest settings-page pass was webapp-only: all 77 Chromium webapp tests and 91 quality checks passed, plus webapp typechecking. Desktop/native and mobile-variation review is deferred; no credentials were imported and no inference was triggered during this pass.

## Performance checks

`conversation-transcript.tsx` isolates transcript rendering from composer updates. `transcript-index.ts` groups parts once rather than rescanning the whole transcript for every message. Unchanged message/part identities skip Markdown rendering during unrelated updates. Composer resizing is coalesced into animation frames, with a persistent width observer instead of observer recreation per keystroke.

Browser regression tests use a 200-message Markdown conversation and test-only React commit instrumentation. They assert that typing preserves every character without rerendering the transcript/Markdown, and attach input-to-next-frame timing samples. Tests also cover dictation resizing, focus trapping/restoration, suggestion/Mason consent and same-intent retry, routine draft persistence and provider model search/grants. Unit tests cover complete 1,000-chunk grouping and safe PR-link parsing.

Latest chat/settings/agent-table verification: 150 browser checks, 158 core tests and 91 quality checks passed; core/webapp/shared-UI typechecks passed. Earlier SDK/shared-UI checks also passed; these are not live inference or physical-device results. The 171-character typing sample recorded zero transcript/Markdown rerenders and p95 input-to-next-frame times of 18.7 ms (desktop Chromium) and 15.5 ms (mobile viewport Chromium). This is an instrumented observation, not a before/after benchmark.

These are local browser tests, including mobile viewport emulation—not physical-device measurements, live provider inference or proof that every performance issue is resolved.
